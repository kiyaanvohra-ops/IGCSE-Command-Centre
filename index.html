The 4-step revision loop

Learn a small chunk → close your notes and recall it → answer exam questions → correct mistakes and retry later. Your error log is more valuable than a page of copied notes.

How to run a 50-minute session

A repeatable routine for focused study.

05 minRecall: write what you already know without looking at notes.
20 minLearn: use your textbook, class notes or trusted syllabus-matched resource to fill gaps.
20 minPractise: answer questions independently, ideally exam-style.
05 minReflect: mark your work, record errors and choose the next action.

How to use your results

Turn each score into a useful next step.

🧭

Below 60%

Rebuild the basics
  • Return to the exact concept you missed.
  • Work through one example, then try a similar question alone.
  • Retest yourself within 2–3 days.
🎯

60–79%

Practise for accuracy
  • Look for repeated error patterns.
  • Practise questions that mix related topics.
  • Redo incorrect questions without seeing the solution.
🚀

80% and above

Build consistency
  • Test the skill later without revision first.
  • Try harder or timed questions.
  • Keep it in your spaced-revision rotation.
🧠

Any score

Study the mistakes
  • Classify the mistake: knowledge, method, wording, or rushing.
  • Write one specific next action.
  • Don't count a question as fixed until you can redo it unaided.

2 · Sign in to sync your progress

Connect your project above, then create an account or sign in.

One-time Supabase database setup
  1. Open your Supabase project and go to SQL Editor → New query.
  2. Run the SQL in the supplied supabase_schema.sql file. It creates a private progress table with row-level security; each signed-in user can read and change only their own row.
  3. Find the Project URL and public Publishable key (or legacy anon key) in your project API settings and enter them above. Do not use a service-role key.
  4. Host this HTML file on your existing HTTPS website (for example, your GoDaddy domain). Opening it directly from Downloads may block network requests.
  5. Create your account here. If email confirmation is enabled in Supabase, verify the email first, then sign in.

Safety: the SQL enables row-level security. Keep it enabled. A public/publishable key is safe for a frontend only when table policies protect user data.

If syncing fails, confirm that the schema SQL ran successfully, the public key belongs to the same project URL, and the igcse_progress table has row-level security enabled.
